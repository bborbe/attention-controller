## Summary

- The board renders the **Allow / Deny** pair on **every** `permission` card, so any permission gate can be answered from the board.
- This removes the two exclusions that withheld the pair: spec 004's headless-only gate, and spec 007's production-touching exclusion.
- The corner X stops clearing on the two classes it still cleared — on a `permission` card it now answers, aliasing `✕ Deny`, on every class.
- The Go change is one line: `row.Decide` stops consulting the two provenance facts. Everything else follows from the markup the pair's presence already drives.
- ⚠️ The two provenance facts become unread. They are **left in place**; deleting their machinery is deliberately not this spec's work.

## Problem

The board renders one-click **Allow / Deny** on a `permission` card only where `row.Decide` is true — a headless worker's park whose task declares no production-touching step. On the two excluded classes the card renders **no answering control**, so the operator's only route to the gate is the session's own pane.

That would be a defensible trade if the excluded card were merely unanswered. It is not: the card is **unanswerable and then consumed**. The corner X is the board's only control there, and on those classes it posts `/close`. A clear is not a lesser act than an answer on a `permission` item — it is a fatal one. `closed` is terminal, the store's transition table carries no `closed` → `answered` row, so the parked worker's own arm answer is refused with `ITEM_CLOSED` and the gate never releases: the park runs its full timeout to the auto-deny and the tool call is denied. Measured on a live park while working the parent row.

So the exclusion did not withhold a *decision* — it withheld the only route to one, and then made the withholding permanent. ⚠️ The second exclusion was justified by a real hazard: spec 007 exists because a one-click board **Allow** on an irreversible park (`make install`, a `launchctl kickstart`, a deploy) launches a destructive action with no confirmation and no undo. The operator has since ruled that the pair renders on those classes anyway, with that hazard quoted on the card that carried the ruling. This spec implements that ruling; it does not re-argue it.

## Goal

After this work, every `open` `permission` card on the board renders the Allow / Deny pair, whichever class it belongs to, and the corner X answers rather than clears on all of them — with no new field, no new lifecycle transition, no change to the pair's markup, and no change to any other card element.

## Non-goals

- **Not a re-argument of the ruling.** The exclusions were overruled, not refuted: a tab worker's answering still happens in its own pane, and a production-touching park is still irreversible. Do NOT add a confirmation step, a second click, a warning interstitial, or any control between the operator and the verdict — the operator ruled on the hazard knowingly.
- **Not the removal of the now-unread provenance machinery.** `provenance.Headless` and `provenance.ProductionTouching` lose their only reader, but the spawn-ledger read (spec 004) and the marker read (spec 007) stay exactly as they are. Deleting them is a separate change with its own blast radius; this spec neither deletes them nor adds a second reader to keep them alive.
- **Not the production-touching marker convention.** `docs/production-touching-marker.md` documents the operator's authored marker; the convention is unchanged and the vault's task files are not edited. Only the board's *consultation* of the marker ends.
- **Not spec 004.** It is `completed` and immutable. This spec supersedes its headless-only gate by shipping a new behavior; it does not edit, reopen or re-verify that file.
- **Not spec 007's prompt trail.** Its three prompts are already executed. Its disposition as a spec record is handled outside this spec's prompts (see Constraints).
- **Not `message` or `ack` controls, the jump corner, the read-aloud control, the provenance line, or the dimmed record card.** None of them changes.
- **Not the release mechanism** in `bborbe/claude-supervisor` (`armDelivery`, the `resolved_by` rule). Untouched and not depended on.

## Security / Abuse Cases

The change adds no route, no input, no credential, no file read and no file write. It renders one existing control in more cases and stops consulting two derived facts.

- **What crosses a trust boundary:** nothing new. The pair's presence was already derived from the item's producer-claimed `LivenessRef` (through the spawn ledger) and from the resolved task file; this change makes the derivation constant, which *narrows* what a producer can influence — no producer claim can now suppress the pair.
- **What must be validated:** nothing new is interpolated into the page. The removed terms were booleans that selected which existing controls render.
- **What can hang or exhaust:** nothing new, and strictly less work than before: two per-page-load reads become unread, though they still run (Non-goals).
- ⚠️ **What must fail safe — and the direction is deliberately flipped, which is the one security-relevant consequence of this change.** Spec 004's headless gate failed **closed** (uncertainty → no control) and spec 007's marker read failed **open** (uncertainty → control). With both terms removed there is no uncertainty left to resolve: the pair renders on every `permission` item, including one whose provenance cannot be resolved at all. The residual is the hazard spec 007 named — a one-click **Allow** on a production-touching park — and it is accepted on the operator's own ruling rather than by omission.
- **The board's answer remains an operator act.** `answered_by` is still a caller declaration and a scripted click still writes the same value as a human one (silence 19); this change does not touch that, and it adds no new control a script could reach — the pair is the control spec 007's census already counted.

## Do-Nothing Option

The two classes keep a card the operator cannot answer, and the corner X keeps consuming the gate: the park runs to its auto-deny and its tool call is denied, with the operator having been shown a card that looked actionable and was not. The cost is paid on every such park, and it is the failure the parent change already fixed one class of. Doing nothing leaves the fix half-applied and the remaining half worse than the class already fixed, because there the operator at least sees a control that does what it says.
