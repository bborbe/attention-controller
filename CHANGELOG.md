## Unreleased

- feat: name the vault task a card belongs to, as a link that opens that task. A card said *where* an item came from — host, cwd, tool, pane — and never *what it was about*, so judging one meant leaving the board and opening the session it named. The provenance line now leads with the task name, drawn as an `<a>` whose href is `obsidian://open?vault=<vault>&file=<path>`: an item whose session resolves to no task renders **no link at all**, never an empty or dangling one, and the link is navigation — it adds no control and changes nothing any card offers. ⚠️ **The gate was the trap.** The template renders the provenance line only `{{if .Provenance.Resolved}}`, and `Resolved` tested `Host`, `Cwd`, `Tool` and `Pane` only — so a `Provenance` carrying **nothing but** a task name rendered **no line at all**, the name resolved correctly, drawn correctly, and never appearing. `Resolved` now admits `TaskName`; the doc comment keeps its meaning ("could anything about this item's origin be told") and says a task name is such a fact. ⚠️ **`TaskURL` is a `template.URL`, not a `string`, and the type is load-bearing.** html/template's URL filter admits only `http`, `https`, `mailto` and relative URLs, so a plain-string `href="{{ .TaskURL }}"` renders `href="#ZgotmplZ"` — the link dead in the browser while every test that asserts on the row field still passes. `obsidian://` is exactly the scheme that filter refuses. The helper carries `// #nosec G203` in the style of `pkg/pane-lister.go`: `template.URL` bypasses html/template's escaping by construction, and the value is built from the operator-configured vault name and a filesystem-derived task path, never from producer input, with **both** halves escaped by `url.PathEscape` — ⚠️ **not** `url.QueryEscape` and **not** `url.Values.Encode()`, both of which render a space as `+` and would silently break the `%20` contract, and the vault name is escaped too because it is only the configured directory's base name. A trailing `.md` is stripped idempotently rather than assumed, since the index's own path field is not specified to carry one. ⚠️ **The link is wrapped in its own `<span class="task">`**, which is required rather than cosmetic: the line's separators come from a rule matching only *adjacent* spans (`.provenance span + span::before`), so a bare `<a>` among the spans would suppress the separator beside it and the line would render as `Fix the boardburn · /w/x`. ⚠️ **The vault directory is plumbed, not read** — `NewAttentionPageHandler` and `NewAttentionStreamHandler` each gain a `vaultDir string`, threaded from `a.VaultDir` through `pkg/factory` from `main.go`, and the name is derived once per render as `filepath.Base(vaultDir)`, guarded so an empty directory yields an empty name (`filepath.Base("")` is `"."`, which would name a vault that does not exist). Both callers of `newAttentionPageRow` pass the **same** derived name, because a row arriving over the SSE stream must not differ from the same row on a fresh load — the invariant that handler exists to preserve. Specs: three new cases in `pkg/handler/attention-page_test.go` driving the page handler and scoped with `rowOf` (an anchor with the expected href and text; **no** anchor for a task-less row, whose fixture carries a host so the absence assertion cannot pass vacuously; and a task-**only** provenance still rendering its line), a case in `pkg/handler/attention-stream_test.go` asserting the streamed row carries the same anchor, and two cases in `pkg/provenance_test.go` for `Resolved`. The expected href is a **hand-written literal** in both files — a shared helper would agree with itself whatever it produced — written as the served markup reads it, `…vault=Personal&amp;file=25%20Tasks%2F…`, since html/template escapes the `&` in the attribute. Each of the three failure modes was proven falsifiable: reverting the `Resolved` conjunct reddens three specs, wiring the stream with an empty vault name reddens one, and widening `TaskURL` to a plain `string` reddens three.

- feat: resolve the vault task an attention item's session is anchored to, as a new provenance source. The board could say *where* a session ran — host, cwd, tool, pane — but never *what* it was working on, so judging a card meant leaving the board and opening the session it named. `pkg/provenance.go` gains a `TaskIndex` built once from a configured vault: it reads every `*.md` under `<vault>/25 Tasks/`, takes the `claude_session_id` from each file's YAML frontmatter — parsed by hand, because `go.mod` carries a YAML parser only as an indirect dependency and no Go file imports one — and joins it to the item's session id via the existing `sessionIDFromItem` helper. ⚠️ **Several task files may share one session id** (measured live: 33 session ids map to between 2 and 6 files), so the tie-break prefers the file whose `status` is neither `completed` nor `aborted` and falls back to the lexicographically last path. `Provenance` gains `TaskName` and `TaskPath`; the renderer derives the vault's own name from the configured directory, so no third field carries it. ⚠️ **The task lookup is independent of the pane lookup** — it runs after either branch and creates the item's `Provenance` entry when neither claimed anything, because `resolveByName` reports `ok=false` on an unreadable pane listing, an unregistered session or a non-matching pane, and the task name would otherwise be lost for exactly the items whose producers wrote no event log. It fails soft in every direction: an empty, missing or unreadable vault, an unreadable file and a malformed frontmatter block each yield no task for the affected rows rather than failing the page, logged at `V(2)`/`V(3)` as `sessionNames` does. New `-vault-dir` / `VAULT_DIR` flag, deliberately **without** a default — an unset vault renders no task names rather than pointing at a guessed path. ⚠️ **Nothing renders differently yet**: no template or factory changes, `Provenance.Resolved()` is untouched, and the name is carried but not drawn — rendering is a later prompt.

- refactor: derive an attention card's control set from the item's answer mechanism in one `affordance` switch in `pkg/handler/attention-page.go`, replacing the two independent comparisons against `pkg.MessageAnswerMechanism` and `pkg.AckAnswerMechanism` that `newAttentionPageRow` carried. The two predicates read as a single derivation without being one — nothing in that shape stated that a mechanism holds at most one affordance, so a mechanism matching neither fell through to whatever the template's `else` branch happened to be, which is how a report-only `ack` card once rendered nothing at all and how an `ack` card inherited a `permission` card's shape by accident. The switch's `default` is deliberate: a mechanism the board has not been taught renders no control rather than inheriting one, and `permission` reaches that arm today. **No card renders differently** — the mechanism-to-pair mapping is unchanged and both callers of `newAttentionPageRow` (the page handler and the SSE stream at `pkg/handler/attention-stream.go`) share the one derivation. Adds a `DescribeTable` in `pkg/handler/attention-page_test.go` that iterates `pkg.AvailableAnswerMechanisms` rather than listing the members by hand, asserting the rendered markup of each item's row, so a fourth mechanism fails until its affordance is decided.

## v0.25.2

- fix: keep a board failure visible, and say when the live stream has stopped. Two holes remained in the error surface the previous change opened. **A failure note was destroyed the moment the stream replaced its card's node** — `upsertRow` writes `row.outerHTML` for a visible row and `parked[hidden].html` for a filtered one, and both take whatever was appended inside with them — so an operator reading a note lost it mid-sentence. Notes now survive the swap: the most recent failure per item id is kept in a `failures` map, mirroring the `speaking` map that already solved this exact problem for the read-aloud toggle, and re-rendered after the node is replaced. The entry is **deleted when that action next succeeds**, because a stale failure note that outlives its cause reports a failure that is no longer true — a worse defect than the one being fixed. **A stream that had died permanently left the board frozen at its load-time state with no signal at all**, so a stale board read as a current one; `source.onerror` now renders a not-tracking state in the board's control row beside the **Hide answered** switch, cleared on the next message. ⚠️ **EventSource still owns reconnection** — the handler renders a state and returns; there is no retry loop, no `close()`, and the deliberate absence of a reconnect handler is unchanged, with the comment extended rather than reworded to say what the new handler does and does not do. ⚠️ **The `attention board: ` prefix stays reserved** for the nine action lines the previous change added, and a spec now asserts it is still exactly nine, so a later change that widens it fails loudly instead of silently.

## v0.25.1

- test: add a browser-driven e2e harness for the attention board's post-load behaviour, and gate releases on it. The board's tests asserted on served HTML by substring, so a defect that appears only after the page loads shipped unless someone poked it by hand — which this repo's history records happening more than once (v0.19.0's inert read-aloud button: present in the markup, dead on click, no request made). The suite builds the real binary, runs it on a random port against a temp `DATADIR` and a temp session registry with an `httptest` tts stub, and drives Chromium over five cases: the **Hide answered** switch's click *handler* (not merely the switch's server-rendered presence, which no JS touches and which a substring assert already covered), a fresh load's default view, the `hide=none` view, a row removed after its item is answered over the SSE stream, and the read-aloud control forwarding the utterance to `/say`. It is **not** part of `precommit` and never runs per commit or PR — `//go:build e2e` keeps `go list ./...` from seeing the package at all, so `test` and `precommit` are unchanged; `make e2e` triggers it, and `scenarios/001-board-browser-cases.md` runs it as the pre-release gate. Each case is proven falsifiable: five deliberate breaks (dropped switch click handler, flipped hide default, ignored `hide=none`, skipped SSE row update, dropped speak POST) each turn their case red, and reverting turns it green. ⚠️ **The server-side hide default is not observable post-load** — the server renders every row and passes `HideAnswered` only as the switch's initial `aria-checked` position, while the page's script re-derives the same reading from the URL, so a break of the Go default reddens nothing and a future change there must move the script's literal with it. The driver is pinned to the legacy module path `github.com/mxschmitt/playwright-go v0.6201.1` in `tools.env`: the community path is refused by `go get` from v0.6100.0 on, and its last usable version v0.6000.0 bundles Playwright 1.60.0, whose driver the retired azureedge CDN answers with a 404.

## v0.25.0

- feat: log every attention-board failure to the browser console, and catch the throws nothing caught. The board rendered each failure only as a transient inline note beside the control and wrote nothing to the browser console, so a card that misbehaved left no evidence once the note scrolled out of view or the stream replaced the row — and this repo's own history records that failure class shipping three times: v0.19.0's answer handler threw and fired no request at all while the control still rendered correctly; v0.22.1's Jump control went inert on any card the stream had re-rendered; and the close handler's null-container throw, whose comment on disk reads *"the throw was invisible: the operator saw the right outcome and only the console took the error."* That sentence was already false in the helpful direction — with no `console.error` anywhere in the page, the error was invisible in the console too. Adds a `console.error` on every fetch-failure branch and every `.catch` — nine lines across the four actions, all sharing one `attention board: ` prefix so a devtools session can grep them — plus `window.onerror` and `unhandledrejection` handlers registered at the top level, and a guarded `JSON.parse` on the live-update stream so an unreadable frame is logged and skipped rather than aborting that event's row swap. ⚠️ **Nothing the operator sees changes**: the note helpers' text, placement and `failed` class are byte-identical, and the two global handlers log only — an uncaught error has no form and no row to host a note, so a page surface there would be a new visible element on a path that renders none. The close control's console line uses the fixed word `close` while its note keeps the row-dependent `Acknowledge`/`Clear` verb, because a console line is grepped and the note addresses the operator.

## v0.24.1

- fix: restore the answer form on `message` rows — radios, checkboxes, the `Other…` field, `Dismiss` and `Submit answer` — reverting v0.23.4's display-only change. The operator's report, 2026-09-27: *"ui is now broken … we had radio boxes, check boxes and inputs … i want a quick fix"*. The corner X on `message` rows is restored to its pre-v0.23.4 act with it.
- feat: default the board's **Hide answered** filter to **on**, so a fresh load of the board shows only the cards that still need the operator instead of mixing the dimmed answered records in with them. The operator asked for it verbatim: *"can we make hide answers the default — so open http://127.0.0.1:18080/ ... show no answer?"* ⚠️ **This deliberately reverses the default the switch shipped with, and the reversal is recorded rather than quietly applied.** The original default-off rested on a stated rationale — the dimmed record is the cheapest detector for an answer recorded in the operator's name that they did not give, so *"a board that defaulted the filter on would delete that detector rather than add a view"* — and the operator's newer word is the authority that rationale was waiting for. The detector survives the reversal because the property it depends on is unchanged: **the hidden rows are still served**, still parked client-side and still one toggle away. What changed is their presence in the **default** view, not their existence. **The off-spelling is `hide=none`** — once absence means *on*, "off" needs a value the script can write back, and `none` names the hidden set as empty, which is the same "the value names the set that is hidden" rule the parameter was built on. The test is therefore `!= none` rather than `== answered`, so an unrecognised value falls back to the default instead of silently disabling the filter. Both mirrors move together — the Go consts and the script's literals — and the spec that pins them is extended to the third literal. The URL still carries the parameter only when the view departs from the default, so a fresh load stays parameter-free and `replaceState` keeps the no-reload property intact. The schema page was amended **before** the code, per `attention-controller/CLAUDE.md` § Schema discipline, because it is the spec the renderer implements and it stated the old default.


## v0.24.0

- perf: **a read decodes the live items instead of the whole store — 12,472 decoded to return 46 becomes ~131 for the same 46.** The read path scanned the items bucket and JSON-decoded every stored item before `classifyForRead` filtered to the open ones, so the cost tracked store size rather than the live set — a factor of roughly 270× on the census this was filed from, and the CPU cost that kept the process above 100 % at idle after v0.23.2 removed the writer lock held *around* the scan. A second bucket, `attention-live-index`, now holds every item whose state is not `ClosedState` — the exact set `classifyForRead` can keep or remove — and `readItems` scans that instead. ⚠️ **Every mutation routes through one choke point** (`putItem` / `removeItem`), because the index is correct only while every write maintains it: atomicity is free, since both writes share one bbolt transaction, but a call site reaching for `a.store.Add` directly would drift the index and the read would silently *under-return* rather than fail. ⚠️ **The read's contract is unchanged** — the same returned set and the same prune, still a compare-and-delete that re-reads state and liveness inside its own transaction — and a steady-state read still opens **no write transaction**: `putItem` writes the index marker when it creates a store's first item, so a fresh store never builds, and a store migrated from an older version builds once, on its first read. Evidence: `pkg/read-decode-count_test.go` counts `Item.Value` invocations through a wrapping DB → Tx → Bucket → Iterator → Item chain — **red on the pre-fix revision** (1,000 closed → 1,050 decodes; 20,000 closed → 20,050) and **green on this one** (51 and 51 — the live set plus the marker), both run back to back on the same machine. Change set: `pkg/attention-store-impl.go`, `pkg/read-decode-count_test.go`.

- feat: **the board's read-aloud control is a toggle — clicking it while its own item is playing stops that playback.** It previously POSTed `/api/1.0/attention/{itemID}/speak` on every click, so a second click queued a *second* reading rather than stopping the first, and a reading once started could not be stopped from the board at all — the operator's report, verbatim, 2026-09-27: *"It starts reading, but I can't cancel."* ⚠️ **The stop is scoped to the board's own utterance and never drains the queue.** `POST /api/1.0/attention/{itemID}/cancel` is a new proxy to the tts server's `/cancel`, and its request struct carries **no `all` field** — so a body-less or `{all: true}` cancel is unrepresentable rather than merely unused. The tts server is a single queue every session speaks through, so a drain would cut off another session's narration: a worse defect than the one-way control this replaces, and the reason the field is absent rather than false. A missing `message_id` is refused with 400 before anything is forwarded, because the only default the tts server offers is "stop whatever is playing". ⚠️ **The tts server's 404 is reported as a not-found, not as a gateway failure** — it means the id aged out of the server's TTL-pruned status table, so the reading is over and there is nothing left to stop; the page treats it as a successful stop and returns the control to idle rather than stranding the operator on a stop button that cannot stop anything. ⚠️ **The message id lives in the page's script scope, not on the button.** `upsertRow` replaces a row's whole `outerHTML` on every stream event, so an id written onto the control dies with the node — the same defect one layer down. Held in the closure it survives every re-render, the click handler decides from the map rather than from `data-state` (so the control's *action* is right even in the window before the repaint lands), and `upsertRow` re-applies the repaint after each swap. It does not survive a full page reload; that limit, and why it was accepted over a handler-process map, is recorded on the task page. ⚠️ **The two states are told apart by colour only** — `[data-state="speaking"]` takes the palette's existing affirmative green on `color` and `border-color`, with the glyph, the size and the corner placement untouched, so the `v0.19.0` geometry and the icon-only markup still hold. `aria-label` / `title` swap to *"Stop reading"* in that state, so the control's name matches its action. Change set: `pkg/handler/attention-cancel.go` (new), `pkg/handler/attention-cancel_test.go` (new), `pkg/handler/attention-page.go`, `pkg/factory/factory.go`, `main.go`.

## v0.23.5

- fix: stop rendering the read-aloud control on the dimmed record card, which the schema forbids. ⚠️ **The card is a record, not a prompt.** [[Attention Item Schema]] line 234 states the rule verbatim — *"It renders no form, no option row, no `Other…`, no Dismiss, no Next, no acknowledge control, and no Read aloud — a control on it would offer an answer to a question that already has one."* The read-aloud control asks the tts server to read the **question** aloud, which is the act of a prompt, on a row whose whole purpose is to be the record of a settled one. ⚠️ **The gate gains a `.Dimmed` conjunct:** `{{if .Speak}}` becomes `{{if and .Speak (not .Dimmed)}}` at `attention-page.go:990`. ⚠️ **This is NOT a regression of v0.23.3, and the distinction is load-bearing.** That release dropped the gate's `Message` conjunct, and a dimmed `message` card carries `Message == true`, so `and .Message .Speak` and `.Speak` were already **equivalent** on that row — the dimmed card carried the speaker before v0.23.3 too. The defect is older than that PR; this fix is not an undo of it, and a reader who assumes otherwise will look for the wrong lever. ⚠️ **`.Dimmed` was chosen because it is exactly the predicate the rule needs, and the template already uses the idiom.** It is set at `:1191-1196` precisely when `item.State == pkg.AnsweredState`, so it is mechanism-independent and the one conjunct covers the dimmed `message` **and** dimmed `permission` cards alike; the ack control at `:1009` already reads `{{if and .Ack (not .Dimmed)}}`, so the fix reads as the template's existing rule rather than as a new one. **Rejected:** a new `attentionPageRow` field (duplicates a predicate `.Dimmed` already carries, creating a second source of truth that can drift from it), a `Message` conjunct (narrower than the rule — a dimmed `permission` card would keep the control), and post-render string surgery (this repo stays inside `html/template`). ⚠️ **The schema was checked BEFORE the code moved, per § Schema discipline, and the outcome is that it did NOT need amending.** `git log -S "no Read aloud"` dates that phrase to **2026-09-26** — a day before the defect was observed and a day before v0.23.3 — so the render never complied. Recorded rather than amended, with the near-miss noted on the task page: § Answer routing's `any` / `answered` row says *"no **answering** control"*, which is narrower than the card's own rule, since the schema itself classifies read-aloud as *"a utility that records no answer"*; the row's delegation clause (*"rendered per § The dimmed record card"*) is what carries the weight, and it holds. ⚠️ **One new spec asserts both halves in a single render, deliberately.** A dimmed `message` card and a dimmed `permission` card must carry no `data-speak`, **and** the three legitimate carriers (`message`/`open`, `ack`/`open`, `permission`/`open`) must still carry it in that same document — so a fix that removed the control everywhere fails rather than passing, and the negative alone cannot be satisfied by a page that rendered nothing. It was verified to **discriminate** rather than merely to pass: reverted to `{{if .Speak}}` it goes red, failing on the dimmed card's own `data-speak`. Every assertion is scoped to the row's own block via `rowBlock`, never the body, since `data-speak` also appears in the page's own script (`querySelectorAll('button[data-speak]')`) — a body-wide check finds a copy whether the card renders the control or not. A second spec covers the rest of the schema's line-234 list (no option row, no `Other…` field), which the existing dimmed-card spec did not assert.

That is a new site in the same family the `answered_client` census covers, and it is handed to [[A Scripted Browser Click Is Indistinguishable From the Operator's Own]] rather than half-fixed here. ⚠️ **Schema first**, per `CLAUDE.md` § Schema discipline: [[Attention Item Schema]] is amended in **seven** places before this code change — the Lifecycle `open` → `closed` row, the control-set table's `permission`/`open` row, the § *The corner X* paragraph **and** its per-mechanism table row, the two boundary sentences still reading *"a `permission` card is untouched"*, silence 20's restatement of the old bound (*"including no corner X"*), and the census pointer. The note's verb is now read off the row. ⚠️ **Four specs asserted the old behaviour and are amended rather than deleted** — the inverted negative control in `attention-page_test.go`, which now asserts a permission row **carries** the X so a regression that re-excludes it fails, and three in `attention-board-page_test.go` that used `NotTo("<button")` as a proxy for *"carries no control"*. ## v0.23.2

- fix: stop a list read from holding a write transaction across its whole scan, so it no longer starves every Push behind it. `read()` opened `db.Update` — a **read-write** transaction — and held it across a scan that JSON-decodes **every** item *and* runs a per-item liveness check that does file I/O (an `os.Stat`, or up to **70** uncached session-registry reads). bbolt permits one read-write transaction at a time, so every list read blocked every other read *and* every write for the length of that scan. The handler diffs the rows it last sent, so it reports a change rather than the whole board and never replaces a row the operator is typing into, and it is deliberately not wrapped in `libhttp.NewJSONErrorHandler`, which buffers a whole body before writing and would deliver nothing until the connection closed. The two `location.reload` calls that fired after an answer or an acknowledgement are gone: each action's own effect arrives over the channel, and reloading would defeat the channel's own negative control.
