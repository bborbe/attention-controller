# Resolve duplicate suppression by a point read of a derived dedup index

<summary>
- A push no longer walks the whole store to decide whether a card already exists.
- Duplicate suppression becomes a single lookup keyed on the producer and its dedup key.
- A duplicate re-push and a fresh create cost the same whether the store holds 40,000 items or 400,000.
- The lookup is a persisted index, maintained by the same write path every other index uses.
- The index holds open items only, so it can only return a row suppression may collapse onto.
- The index carries a built-marker; a lost or drifted index is rebuilt from the store before it is read.
- Closing one of two rows that share a key leaves the surviving row's entry intact.
- Dedup semantics do not change: a live producer still collapses, a dead one still gets a new row.
- A probe measures how many stored items a push decodes, for the hit and the create path alike.
- The item's field set is untouched — this is a storage layout, not a schema change.
</summary>

<objective>
Resolve duplicate suppression in the attention store by a point read of a new persisted derived index keyed on `(producer_id, dedup_key)`, so the cost of a push stops depending on how much the store has accumulated.
</objective>

**Why this change.** Today `findOpenByDedupKey` walks the **entire** items bucket and decodes every stored item, and two independent facts make that the dominant cost of a push. The walk never short-circuits — its guard is `if found != nil { return nil }`, and a `nil` return from a `libkv` `Map` callback **continues** the walk, so the scan runs to the end of the bucket whether or not it matched on the first row. And `updateExistingIfLive` runs **before** `newItem`, so the create path — the common one, with nothing to match — pays the same full scan. Measured 2026-10-12 on the deployed store (38,194 items, `bolt.db` 147 MB): idle `POST /api/1.0/attention` 0.10–0.19 s (n=8), 0.42–1.11 s under 6 concurrent readers, a **2.26 s** peak under 20. The scan runs inside the same BoltDB write transaction the read path contends for, so it holds the single writer lock for its whole duration.

The pinned dependency's `Map` semantics are the whole premise of the fix, so they are recorded here verbatim from `github.com/bborbe/kv@v1.21.17/kv_store-tx.go`:

```go
func (s storeTx[KEY, OBJECT]) Map(
	ctx context.Context,
	tx Tx,
	fn func(ctx context.Context, key KEY, object OBJECT) error,
) error {
	bucket, err := tx.Bucket(ctx, s.bucketName)
	if err != nil {
		if errors.Is(err, BucketNotFoundError) {
			glog.V(3).Infof("bucket %s not found", s.bucketName)
			return nil
		}
		return errors.Wrapf(ctx, err, "get bucket failed")
	}
	it := bucket.Iterator()
	defer it.Close()
	for it.Rewind(); it.Valid(); it.Next() {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
			item := it.Item()
			key := KEY(item.Key())
			err := item.Value(func(v []byte) error {
				var object OBJECT
				if err := json.Unmarshal(v, &object); err != nil {
					return errors.Wrapf(ctx, err, "unmarshal %s failed", string(key))
				}
				if err := fn(ctx, key, object); err != nil {
					return errors.Wrapf(ctx, err, "call fn failed")
				}
				return nil
			})
			if err != nil {
				return errors.Wrapf(ctx, err, "handle value failed")
			}
		}
	}
	return nil
}
```

A `nil` return from `fn` CONTINUES the walk; the loop exits early only on a non-`nil` error or a cancelled context. `item.Value(...)` is called exactly once per entry, and that callback is where `json.Unmarshal` runs — which is why one `Value()` call is one decode, and why the probe wraps that method.

   ```go

   // suppression against. It holds a copy of every item whose state is
   // `OpenState`, keyed on `producer_id` and `dedup_key` rather than on the item
   // id — the one index in this file whose key is not the items-bucket key.
   //

   // only ever collapses onto an open row, so `findOpenByDedupKey`'s state guard
   // is satisfied by construction and the index can never return a row the old
   // scan would have skipped.
   //

   // schema — the item schema is untouched — and it is derived data, rebuildable
   // from the items bucket.

   // and the same reasoning as its three siblings.
   //

   // while the marker is one.
   ```

4. **Add the dedup index's two maintenance helpers**, in `pkg/attention-store-index.go`, beside `reconcileIndex` and `removeIndexKey`.

   ⚠️ The removal is **scoped to the row being removed**, and that is a correctness requirement rather than tidiness. Two open rows CAN share one `(producer_id, dedup_key)` — that is exactly what the dead-producer path produces — and the index holds one representative for the pair. A removal that deleted the entry by key alone would remove the *surviving* row's entry, and the next re-push of that key would then write a third row. The compare-and-delete below is what `removeIndexKey` cannot express.

   ```go
   // reconcileDedupIndex brings the dedup index in line with one item: an open
   // item becomes the entry for its `(producer_id, dedup_key)`, and any other
   // state drops the entry — but only when the entry IS this item.
   //
   // ⚠️ `previous` is deliberately not a parameter. The key is derived from
   // `ProducerID` and `DedupKey`, the two fields `updateExistingIfLive` never
   // rewrites, so — unlike the history index, whose key is derived from
   // `CreatedAt` and therefore MOVES — this key is immutable for a given item
   // and there is no stale key to clear.
   func (a *attentionStore) reconcileDedupIndex(
   	ctx context.Context,
   	tx libkv.Tx,
   	item Item,
   ) error {
   	key := dedupIndexKeyOf(item.ProducerID, item.DedupKey)
   	if openIndexWorthy(item) {
   		if err := a.dedupIndex.Add(ctx, tx, key, item); err != nil {
   			return errors.Wrap(ctx, err, "add dedup index entry failed")
   		}
   		return nil
   	}
   	return a.removeDedupIndexEntry(ctx, tx, key, item.ItemID)
   }

   // removeDedupIndexEntry removes the entry under key ONLY when that entry is
   // this item's, and treats "no entry" as success so callers stay idempotent.
   //
   // ⚠️ The ItemID compare is load-bearing, not defensive. Two open rows can
   // share one key, so the entry under it may belong to the other row; removing
   // it would leave that row unindexed and let the next re-push of the same key
   // write a duplicate — the operator-visible defect this store already carries.
   // A mismatch is therefore LEFT for the rebuild rather than guessed at.
   //
   // ⚠️ The mirror case is NOT covered, and it is the spec's Failure Modes row 2:
   // when the REPRESENTATIVE itself closes while a sibling open row survives, this
   // removal is taken and the survivor is left unindexed until the built-marker is
   // dropped and a later push rebuilds. Do not read the compare above as a
   // guarantee that every open row is indexed.
   //
   // The Get is also what makes an absent bucket safe: `StoreTx.Get` on a bucket
   // that was never created fails with an error `isNotFound` recognises.
   func (a *attentionStore) removeDedupIndexEntry(
   	ctx context.Context,
   	tx libkv.Tx,
   	key string,
   	itemID ItemID,
   ) error {
   	entry, err := a.dedupIndex.Get(ctx, tx, key)
   	if err != nil {
   		if isNotFound(err) {
   			return nil
   		}
   		return errors.Wrapf(ctx, err, "get dedup index entry %s failed", key)
   	}
   	if entry.ItemID != itemID {
   		return nil
   	}
   	if err := a.dedupIndex.Remove(ctx, tx, key); err != nil {
   		return errors.Wrapf(ctx, err, "remove dedup index entry %s failed", key)
   	}
   	return nil
   }
   ```

   ⚠️ `openIndexWorthy` is reused as this index's predicate rather than a new `dedupIndexWorthy` being written. It is `item.State == OpenState`, which is exactly the set suppression can collapse onto; a second predicate spelling the same test is the copy that drifts. Say so in a comment.

5. **Add `ensureDedupIndex`**, in `pkg/attention-store-impl.go` beside `ensureLiveIndex` / `ensureOpenIndex` / `ensureHistoryIndex`, but with **one deliberate difference: it takes the caller's `libkv.Tx`, not the DB.** `Push` already holds bbolt's single writer lock for the whole push, so an ensure that opened its own `a.db.Update` would deadlock against it — this is the "`Push` opens no second write transaction" constraint, and taking the `tx` is what makes it structurally impossible rather than merely discouraged.

   ```go
   // ensureDedupIndex builds the dedup index if it has not been built, inside the
   // CALLER'S write transaction, and is a no-op otherwise.
   //
   // ⚠️ It takes a tx rather than opening its own Update, and that is the whole
   // difference between this and its three siblings. `Push` already holds
   // bbolt's single writer lock for the length of the push, so an ensure that
   // called a.db.Update here would deadlock against it. Every other reader of a
   // derived index runs on the read path and can afford a transaction of its
   // own; the dedup index's only reader is inside a write.
   //
   // ⚠️ The marker is re-checked INSIDE the caller's transaction, which is also
   // what makes two writers racing the first push on a marker-less store safe:
   // bbolt admits one writer at a time, so the loser finds the marker already
   // written and does no work rather than rebuilding twice.
   func (a *attentionStore) ensureDedupIndex(ctx context.Context, tx libkv.Tx) error {
   	built, err := a.dedupIndex.Exists(ctx, tx, dedupIndexMarkerKey)
   	if err != nil {
   		return errors.Wrap(ctx, err, "check dedup index failed")
   	}
   	if built {
   		return nil
   	}
   	if err := a.rebuildIndex(
   		ctx,
   		tx,
   		a.dedupIndex,
   		dedupIndexMarkerKey,
   		"dedup",
   		openIndexWorthy,
   		dedupIndexKey,
   	); err != nil {
   		return err
   	}
   	// The marker is written in the SAME transaction as the build, so an index
   	// can never be marked built while half-populated — and a crash mid-build
   	// leaves it unset, so the next push rebuilds rather than trusting it.
   	return a.dedupIndex.Add(ctx, tx, dedupIndexMarkerKey, Item{})
   }
   ```
